# Selective Hearing：选择听谁说话

Windows 本地实验程序：首次识别到人声后生成人物控制，每个人独立选择「听他 / 不听他」，可同时听多个人，也可选择「全部听（原声）/ 全部静音」。目标设备链路为 **AirPods 麦克风 → Windows 推理 → AirPods 播放**，不经过 iPhone。

目前已实现桌面界面、公开录音处理、真实双人波形分离、跨块身份匹配及设备收放音代码。**这是有明显缓冲延迟的原型；AirPods 实机收音与端到端延迟尚未验收。** 测试结论见 [实现与实测](docs/implementation.md)。

## 启动

需要 Windows、Python 3.12（含 Tcl/Tk）、约 2 GB 可用磁盘空间。当前使用 CPU，不要求 NVIDIA 显卡。

```powershell
# 首次安装；模型首次下载需联网，之后推理在本机进行。
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1 -Models

# 主程序：自动加载模型，并使用默认设备开始收音和播放。
powershell -ExecutionPolicy Bypass -File run.ps1

# 独立的音频文件测试程序：自动加载模型，不打开麦克风。
powershell -ExecutionPolicy Bypass -File run.ps1 -FileTest
```

安装完成后也可双击项目中的 `run.cmd` 打开主程序，或 `test-audio.cmd` 打开文件测试程序。启动器按脚本所在位置定位项目和环境，不依赖当前工作目录。若启动失败，运行 `run.cmd -Check` 可查看实际项目路径、运行环境和 Python 版本；“项目环境缺失”不等于电脑未安装 Python。不要仅下载仓库中的单个启动文件运行，它需要同目录的项目文件。

- **主程序：**打开后自动加载本地模型，成功后开始收音。启动时选择 Windows 系统默认输入和输出，并标注「系统默认」；加载期间仍可调整设备，或点「停止」取消自动收音。每 4 秒自动检测设备，连接新耳机后会更新列表，也可点「刷新设备」立即检测。收音或播放期间保留当前设备，不跟随新出现的系统默认设备自动切换；在下拉框选择其他设备后，会停止旧音频、等待当前推理结束，再恢复运行，期间会有短暂停顿。切换保留人物收听开关。使用中的设备断开时停止音频，不自动改用扬声器；选择可用设备后点击开始。设备或模型启动失败时显示原因，不会擅自换用其他设备。
- **音频文件测试：**在独立程序中等模型就绪，点「导入并处理」选择 WAV / FLAC / OGG；生成说话人后点「循环试听」，切换人物。可导出分离音轨和 JSON 报告。此程序没有收音入口，不打开麦克风。
- **说话人：**实时模式默认每 3 秒分析一次，首位人物至少需要 1 秒有效语音，首次识别后就显示可用的「听他 / 不听他」。后续新声音先暂存为候选，需在不同片段重复出现且明显不同于已知人物，才新增按钮；不再因一次声纹波动直接建人。名字可在人物卡片上直接编辑，回车或移开焦点保存；后续识别更新不会覆盖名字。名字、初始声纹和后续学习结果自动保存在本机，重开程序会恢复人物卡片并继续匹配；文件导出的报告保留自定义名字及其音轨 ID。需要采样和计算时间，太短或不清晰的人声可能无法识别。
- **排查设备：**列表使用 WASAPI 音频端点，过滤不支持本程序音频格式的设备，不重复列出 MME、DirectSound 和 WDM-KS 接口。使用 Windows 共享模式转换采样率和声道；枚举只检查能力，不启动收音。设备被拔出、权限或驱动状态变化仍可能导致启动失败。取消「自动识别人声并分离」，可先测试原声与静音。

「停止」关闭输入与播放，也取消尚未完成的自动收音启动；模型可以继续加载，但不会在加载完成后自行收音。切换按钮在软件下一次输出回调生效，已经送入蓝牙/声卡的声音无法撤回。默认播放增益为 40%；使用耳机测试以避免扬声器反馈。

**分析窗口可配置：**在「模型与运行」中输入 1–10 秒，支持小数；回车、移开焦点、开始处理或关闭窗口时保存。主程序默认 3 秒，文件测试默认 4 秒，两者分别记住设置。先停止音频再修改。较长窗口能提供更多语音上下文，但首次输出需等待窗口收满再计算；1.5 秒响应更快，在当前公开样本上更容易漏识别。

**发言状态：**识别到的人物在说话时显示绿色边框和「● 正在说话」，短暂停顿保留约 0.3 秒，之后恢复灰框；停止音频立即熄灭。状态基于播放时间轴上的已识别人声音轨，不受「不听他」和播放音量影响。它随处理后的音频显示，存在采样和推理延迟；未匹配人物及分离残留可能造成漏亮或误亮，不能据此保证现场识别准确。

只有一次识别的首位人物标注「确认中」，此时也可选择；后续块继续确认身份。其他新声音未达到建人条件时，「模型与运行」显示确认进度、有效语音秒数，或输入太弱、归属不明确等原因。候选会过期，未确认片段不补播。已登记人物数量不限制为两人，人物多时可滚动列表；重新开始收音或导入文件会恢复已保存人物，并重置本轮收听开关。每个人的开关独立保存，点 A 的「听他」不会改变 B、C。全部静音后新人默认不听；从「全部听」开始调整时，新人默认听。绿色按钮表示当前选择。

从「全部听」开始关闭人物，再打开最后一个被关闭的人时，自动恢复「全部原声」，不再因这一块没有识别到人物而静音。直接点已开启人物的「听他」也不会改变原声播放。若还有其他人被关闭，或先点过「全部静音」再逐个开启，则继续按人筛选，只叠加已识别且开启的分离音轨，缺失或未知轨道输出静音。

「全部听（原声）」恢复未经人物筛选的原始混合音，包括背景声音。当前模型没有独立背景音输出，暂不提供背景音开关；不能把混合音减去人声的残差直接标成纯背景，否则被关闭的人声可能泄漏。

## 人物资料与持续学习

声纹和名字保存在用户目录的 `Documents/SelectiveHearing/profiles/`。主程序使用 `live-speakers.sqlite3`，文件测试程序使用独立的 `file-speakers.sqlite3`，测试录音不会混入日常人物库。声纹是特征向量，资料库不含原始录音；使用本机 SQLite 文件，不上传，不随 Git 提交。资料未额外加密，请按个人资料保管。

已显示的人物自动保存，包括尚标注“确认中”的首位人物。可用片段（至少 0.5 秒有效人声）的 192 维特征逐段落盘，尚不能确定归属的也会保存；重启后可恢复近期候选证据。样本库保留最近的每人最多 64 段、待定最多 128 段、合计最多 512 段，超过后淘汰较旧样本；初始声纹与学习模板另行保留，不受此限。

改名回车、移开焦点或正常关闭窗口时保存名字。人物卡片显示“样本 N 段 · 追加学习 M 段”：N 是目前归于此人的样本数，M 是通过更严格条件的模板更新次数，刚建档为 0 不代表没有初始声纹。点“删除资料”并确认后，程序停止音频、等待后台退出，再清除名字、模板及归于该人的样本；未确定属于谁的样本不在此删除范围内。取消确认不会停止音频。删除后保持停止，再次听到该人可能重新登记。显示编号从当前最小空缺数分配，删光后从“说话人 1”开始；已有人的编号和自定义名字不变。内部身份 ID 仍唯一，不会把旧识别结果串到新人身上。文件测试程序删除后需重新导入录音。

新片段同时参考各人物最相近的 3 段历史样本、初始声纹和自适应模板；不像已有人的片段先在线聚为候选，跨片段证据足够再建档。原先处于“认不回老人物、也建不了新人”的部分声音，现在可以通过 3 段互相一致的证据和累计 3 秒有效语音建档。不能把所有模糊片段立即强制分给旧人或新人，否则容易重复建人。

新人要求的 2 秒（较难区分时为 3 秒）有效语音是跨窗口累计值；1.5 秒分析窗口也可满足。区别明确的新人至少要两窗、较难区分的至少三窗；实际还需采样和计算时间。单窗有效语音不足 0.5 秒不会加入累计，因此短句、停顿或漏检可能使确认更慢。

新增证据后会复核历史样本：有至少 3 段近邻支持、相似度足够高且明显领先其他人时，待定样本可归档，已分类样本也可以改归其他人物。排除样本自身投票，并保留同一时刻两路来源不能归为同一人的约束。修正影响之后的识别，不补播旧声音，不改人物 ID、名字或当前听/不听选择。暂不自动合并、删除或拆分整个人物档案。

可靠片段仍会更新受约束的自适应模板；初始声纹保留，模板偏移有限。历史样本改归属不会回滚已经发生的模板更新。模型权重没有重新训练，自动归类仍可能出错，不能保证准确率随使用时间单调提高。

公开样本的留出测试中，8 段未参与学习的语音，正确匹配从 7 段增加到 8 段，错配到其他人为 0；这是两名英语说话人的小样本结果，不能保证每次使用或所有现场环境都更准确。仍有短窗漏识别、分离音质和播放连续性问题。详细协议见 [实现与实测](docs/implementation.md)。

本次更新之前仅在旧进程内存中的声纹无法恢复；从此版本开始登记和学习的数据会自动保存。资料库损坏或模型版本不兼容时会显示错误并停止自动收音，不会静默清空资料。命令行 `--file` 和验证脚本默认使用临时身份，不写入日常资料库。

## 下载与排错

基础界面可单独安装 `scripts/setup.ps1`（不加 `-Models`），但人物分离必须安装模型依赖。约 20 MB 分离权重和 83 MB 声纹权重存放在 `models/`；下载和加载均验证 SHA-256。

若官方网络不可达，可自行选择镜像重试：

```powershell
.venv\Scripts\python.exe scripts/download_models.py --hf-endpoint https://hf-mirror.com
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1 -Models -IndexUrl https://pypi.tuna.tsinghua.edu.cn/simple -HfEndpoint https://hf-mirror.com
```

PyTorch CPU 包仍取自官方源。参数只对本次安装生效，不修改全局配置。

安装环境默认位于用户文档目录的 `Codex\sh-runtime-<项目哈希>`，项目 `.venv` 链接到该目录。新建环境时可传 `-RuntimeRoot D:\SelectiveHearing\venv` 指定其他短路径。请确保桌面用户和安装进程都能访问该路径；执行工具能读取目录，并不一定代表桌面启动器也能读取。

```powershell
# 只枚举设备，不收音
.venv\Scripts\python.exe -m selective_hearing --devices

# 离线处理，不播放
.venv\Scripts\python.exe -m selective_hearing --file mixed.wav --output results/my-test

# 控制逻辑测试，不使用真实麦克风或扬声器
.venv\Scripts\python.exe -m pip install pytest==8.3.5
.venv\Scripts\python.exe -m pytest -q
```

## 模型与限制

首版用 **Conv-TasNet Libri2Mix → Silero VAD → ECAPA-TDNN → 会话身份匹配**。先从同一混合波形分离两路，再判断各路是谁；不是根据转写时间戳静音，也不是用干净音轨冒充分离。

主程序目前仍采用上述基线模型。diart 已增加可选的独立验证入口，尚未替换主程序；WeSep、Step 模型未接入。结构、依据和实测边界见 [实现与实测](docs/implementation.md)。

- 实时默认 3 秒分块，离线文件默认 4 秒，均可在软件里设置；非因果模型包含收集音频和计算时间，尚无跨块交叠融合。短窗口和初次声纹可能降低匹配稳定性。
- 分离模型在 8 kHz 工作，输出重采样为 16 kHz 不会恢复高频。
- 身份匹配有可能漏识别或认错；未匹配目标输出静音，绝不自动回退混合声。
- 会话可陆续登记多个人，但当前分离模型每块只有两路输出，不支持可靠分离三人及以上同时说话。人数放开后仍可能误新增或误合并身份，不能承诺中文、嘈杂环境、远场或 AirPods 收音效果。
- 软件静音只控制程序输出，不能消除耳机外部声音或物理漏音。

## diart 独立验证（尚未启用为主程序后端）

已在本机安装 diart 0.9.2，锁定兼容现有 CPU PyTorch 的 pyannote 3.x 和 matplotlib 版本。完整 diart 使用分段、声纹与在线聚类，输出谁在什么时候说话，不直接输出独立人声音轨。标准分段模型需在 [Hugging Face 模型页](https://huggingface.co/pyannote/segmentation-3.0) 接受访问条件，并在本机登录。

```powershell
# 可选依赖；当前这台机器已经安装。
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1 -Diart
.venv\Scripts\python.exe -B scripts/validate_diart.py --check

# 由用户在本机交互式输入 token，不要粘贴到聊天、脚本或 Git。
.venv\Scripts\huggingface-cli.exe login

# 用录音验证完整 diart，不打开麦克风，不修改日常人物库。
.venv\Scripts\python.exe -B scripts/validate_diart.py --file mixed.wav --duration 5 --step 0.5 --latency 1.5
```

结果写入 `results/diart-validation/` 的 RTTM 和 JSON，仅含本次测试的匿名人物和时间段；不是分离音轨，也不声称已实现 diart 跨会话持久身份。`duration` 是重叠滑动上下文，`step` 是推进步长，与主程序当前互不重叠的分析窗口不同。模型首次下载需要网络及有效授权；不会上传录音。

当前验证了真实 diart 库导入与合成模型下的流式接口、输出时间范围、错误处理；因本机尚未登录，真实分段权重尚未运行。不能把这些程序测试当作 diart 识别效果或现场性能证明。完整流程通过公开样本评测后，才继续将其身份与现有分离播放、持久人物库对接。[环境记录](docs/evidence/diart-environment.json)。
