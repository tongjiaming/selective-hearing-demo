# 五人分类优化与验证（2026-10-15）

此次修复针对“五个人陆续说话，重复建成十个人”。没有设置五人上限，也没有仅隐藏重复卡片。更新后仍清空旧学习资料，保留分析窗口设置。

## 改了什么

- 首个人物仍立即建档。后续单个异常片段不再直接创建永久人物，至少经过两个窗口的相似证据；至少一段当前有效人声达到 0.75 秒，或累计三段高度一致的短句。
- 候选档案优先用当前语音足够、声纹上下文较完整的一段作为初始参照。换人时的短过渡片段不再通过候选均值决定长期声纹。
- 匹配门槛从短窗 0.35 调到 0.40，减少不同人仅凭边缘相似度被吸收；没有放松严格学习条件。
- 分开保存“当前新增有效语音”与“声纹实际使用的上下文有效语音”。以前当前尾句不足 1 秒，即使声纹用了完整上下文也不能学习；现在按上下文判断质量，按新增部分累计发言时间。仍只允许互不重叠的上下文作为独立学习参考。
- 新增单次长异常、换人过渡、短句建档、重启恢复、上下文质量持久化与防重复学习的回归测试。
- 已有首个人物后，同窗候选按当前语音完整度、上下文及确定性规则处理，再把结果映射回原输出顺序，避免分离器交换输出次序就改变新人的声纹参照。

## 测试方法

使用 Resemblyzer 仓库中 LibriSpeech test-other 的十位公开英语说话人，每人两个不同录音。分两组，每组五人依次讲话，再倒序播放各人的另一段录音。每轮截取最多 6 秒或 2.4 秒，中间留 0.2 秒空白；分析窗口 1.5 秒，过去上下文最多 3 秒。

模型实际处理混合波形，干净来源仅用于测试评分，身份算法拿不到真实标签。新旧分类器使用同一批模型特征，旧版为 `b4ad4de`。完整来源、文件哈希、预测和结果见 [JSON 证据](evidence/five-speaker-classification.json)。脚本固定了来源提交，可复现。

两组都参与了本轮开发：第二组最初留出，发现问题后也用于改进声纹参照选择。因此最终结果是**开发回归，不能当作盲测或现场准确率**。

## 单次结果

“正确片段”使用人物 ID 与真实人物的最佳一对一映射；分母只计波形来源明确的分离轨。未分类也在分母中，不能只看最终人数。

| 场景 | 档案数：旧→新 | 正确片段：旧→新 | 未分类：旧→新 | 本次结论 |
|---|---:|---:|---:|---|
| 第一组，每人最多 6 秒 | 6→5 | 23/41→31/41 | 13→10 | 重复建档及混人减少 |
| 第二组，每人最多 6 秒 | 5→5 | 21/36→21/36 | 12→15 | 旧版人数正好但同时拆人、混人；新版已分配片段不再出现这些错误，代价是多 3 段未分类 |
| 第一组，每人最多 2.4 秒 | 4→4 | 10/17→10/17 | 7→7 | 仍漏建一人 |
| 第二组，每人最多 2.4 秒 | 6→6 | 11/20→9/20 | 8→10 | 仍重复建人，短轮换覆盖率下降 |

两组 6 秒场景，已分配片段中的同人拆分和异人合并均降到 0；两路模型输出反序、同批特征重复十次也维持五个档案。反复重放同样特征不是十次独立录音，不能据此宣称长期稳定。

另外，原有 8 个一至三人公开样本场景均通过人数和防混人回归；证据见 [enrollment-classification.json](evidence/enrollment-classification.json)。该文件沿用更早的 `edbf656` 全流程对照，不能把其差值全部归因于本次更新。

自动测试：**157 passed**，17 条来自 rx 的弃用提示。无真实麦克风录音、无私人声纹上传。

## 仍需解决

快速换人、很短的语音、距离变化、分离失真仍可能导致重复或漏建。第二组快速轮换甚至比旧版少正确识别两段，不能称为全面提升。

单路麦克风 + 固定双输出分离器并不等于成熟的多人日常识别系统。后续优先收集有许可、带真实人物标签的中文现场样本，固定开发集和新留出集，同时看建档延迟、漏认、混认、拆人、计算耗时。再评估真正的说话人变化检测、分段/聚类后端；diart 当前仅为独立验证入口，尚未接入主程序，且分段结果本身不会生成可静音的独立波形。

## 复现

在项目目录执行（不会开启麦克风）：

```powershell
.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider
.venv\Scripts\python.exe -B scripts\validate_five_speakers.py
.venv\Scripts\python.exe -B scripts\validate_identity_classification.py --output docs/evidence/enrollment-classification.json
```

五人脚本首次通过 `gh` 下载固定版本的公开 FLAC，音频和特征缓存只放进被忽略的 `work/`。GitHub 仅保存代码、来源哈希与汇总证据。
