# 首版实现与实测

更新至 2026-10-15。本页记录代码和本机实验；diart 已安装并增加独立验证入口，真实模型等待授权，尚未切换主程序。WeSep 仍为后续候选。

## 已实现

原生 Tk 主程序打开后自动加载模型，成功后按选中的设备开始收音和播放。列出通过格式检查的 WASAPI 设备，启动时选择系统默认输入/输出；加载期间点「停止」会取消自动收音。模型或设备启动失败时显示错误，可重试；可手动选择并在停止音频后刷新设备。`selective_hearing.file_ui` / `test-audio.cmd` 为独立的文件测试入口，自动加载模型，没有麦克风收音入口。

人物卡片支持直接编辑名字，回车或失去焦点保存；后续声纹识别状态更新不覆盖名字，也不改变该人物的收听开关。名字绑定本机持久人物 ID，初始声纹、学习声纹、有效观察次数及语音时长自动保存。重新收音或打开程序会加载已有资料；收听开关在新会话重置。文件导出的 JSON 含名字和内部 ID 对应关系，音轨文件仍用固定 ID 命名。

2026-10-15 启动与改名回归：30 项自动测试通过。真实本地模型从打开主窗口到自动开始收音约 3.92 秒；用当前系统默认设备收音 3.02 秒，收到 151 次输入回调，输入和输出流均处于运行状态，停止后两条流都关闭。验证时播放增益设为零，没有保存麦克风音频。独立文件程序另行加载真实模型，处理 17.06 秒公开混合录音发现两人，改名后身份更新和收听开关保持一致，导出 JSON 保留名字。此测试未验证耳内听感或 AirPods 效果。[验证记录](evidence/startup-and-names.json)。

实时 AI 模式把 16 kHz 单声道音频默认每 3 秒交给模型，离线文件默认每 4 秒处理，两者可在界面分别设置 1–10 秒并持久保存。运行中不可修改，停止后生效；非法或非有限数值不会启动处理。Conv-TasNet 在 8 kHz 分离两路波形，依据输入混合波形校准输出增益，再用 Silero VAD 取语音、ECAPA 计算声纹，匹配本机已登记人物及本轮新发现的人物。没有访问干净参考音轨、转写或 TTS。

会话匿名身份数量不限制为两个，但每个模型块仍最多两路声音。匹配阈值为 0.55，有效语音不足 2 秒的短片段为 0.45；与其他身份或候选的相似度差至少 0.10。一个身份在同块只能匹配一路。首位人物有至少 1 秒有效语音时立即生成可用按钮，标注“确认中”；至少两个块、累计 1.5 秒有效语音后去掉标记。

其他新声音需与全部已知人物相似度低于 0.30，先进入候选池；在不同块再次出现、候选相似度至少 0.50、累计有效语音至少 2 秒，并且聚合声纹仍不像已知人物，才新增身份。同一块两路相似输出不能算两次确认。候选从首次出现起最多保留 6 个后续分析块、最多 12 个候选，过期片段不会一直累积为新人；此上限不限制正式人物数量。未确认的候选只显示状态提示，不补播此前片段。初始模板保持固定，另存受约束的自适应模板；匹配和判断新人时同时参考二者。阈值只经过下述小样本回归，未经过真实现场校准。

2026-10-15 重复建人修复：用相同的真实模型输出分别运行旧版 `21200ae` 和新版登记规则。实时 1.5 秒窗中，单人样本从 2 个身份降到 1 个；双人同时说话、先后出现两份样本均从 4 个降到 2 个；降低音量并叠加人工噪声的双人样本从 6 个降到 2 个。4 秒文件模式仍为 2 人。35 项控制测试覆盖一次性异常片段、候选过期、同块重复来源、短窗声纹波动、候选歧义和真正的第三人加入。复现：`.venv\Scripts\python.exe scripts/validate_identity_stability.py`；[完整比较记录](evidence/identity-stability.json)。

这些结果只验证小规模公开英语合成样本。实时双人同时说话样本仍有较多未匹配片段，20 个可用轨道片段只匹配 9 个；按全局身份计算的 SI-SDR 为 0.47 / -6.65 dB。人数稳定不等于分离音质或持续身份匹配已解决。新身份的确认也会推迟按钮和可听音轨出现，文件模式确认前的片段仍为静音。尚未拿用户现场音频做复测。

「全部听（原声）」选原始混合声，「全部静音」选零值。每人的「听他 / 不听他」只更新该人的开关，不改变其他人的选择；音频回调读取不可变的开关快照。切换在下一输出回调生效，时间轴继续前进。全部静音后新人默认不听；从原声状态进行人物选择时，新人默认听。取消最后一个人物排除时恢复原声；仍有排除或默认静音策略时，仅叠加开启的已识别轨道，没有匹配结果就静音。

背景音目前没有独立输出：现有 [Conv-TasNet bundle](https://docs.pytorch.org/audio/stable/_modules/torchaudio/pipelines/_source_separation_pipeline.html) 固定为两路来源，项目接入的是两人语音分离权重。独立背景轨需要接入并验证语音/环境声分离后端，包括人声泄漏和 CPU 延迟测试。不能把当前“混合声减去已识别人声”的残差直接当背景轨；未匹配或分离不完整的人声会留在其中。此能力尚未实现。

2026-10-15 独立开关回归：24 项测试通过，包括陆续登记第三个身份、A/B/C 独立开关、新人继承静音、不可变回调快照和九个人物卡片滚动。真实模型处理两人公开混合录音，验证 A+B 相加、A 开启时 B 保持关闭以及全关输出零值。放开身份数量后曾将末尾 0.8 秒未匹配片段误列为第三人；增加 1 秒新身份语音门槛后，同一输入恢复为两人。这仅修复已发现的短片段案例，不构成三人现场或三人重叠能力证明。证据见 [独立音轨控制验证](evidence/independent-track-controls.json)。

推理在线程中运行，不占音频回调；实时输入队列最多约一个分析窗口，输出最多约两个窗口，过载丢旧块并显示计数。默认 3 秒窗口对应约 3 / 6 秒队列上限，捕获不连续时丢弃未完整拼接的块。未启用模型的原声测试模式输出队列上限 0.2 秒。这些是缓冲上限，不是延迟保证。

离线模式支持导入、分块处理、同时间轴循环试听及导出。导出包含混合音轨、已发现人物音轨和指标 JSON，JSON 区分待确认与已确认身份，不含声纹。实时模式不会自动保存音频。

2026-10-14 首人发现回归：21 项测试通过。真实模型处理公开单人样本的首个 1.5 秒片段，首次识别到 `speaker_1`，尚未确认时 Tk 中两个控制按钮均可用；只听该人有分离波形，不听该人时输出零值。该次计算约 0.716 秒，采样与计算之和约 2.216 秒，不含设备与蓝牙，不是现场端到端测试。证据见 [首人发现记录](evidence/first-speaker-discovery.json)。短窗更早出按钮，但仍可能漏识别或误判；没有把以下 4 秒窗的历史评分外推到短窗。

## 2026-10-15：发言状态、可配置窗口与识别修复

人物卡片增加绿框和“正在说话”。音频输出回调根据当前读到的已识别轨道能量更新状态，RMS 门槛 0.002，维持 0.3 秒跨越短暂停顿。按人静音和播放增益不影响检测，两人同时说话可同时亮起；未输出的待播块不会提前亮起，停止后清除，回调中断后状态也会过期。界面每 100 ms 读取状态；绿框随处理后的播放时间轴，包含模型采样和推理延迟，不是现场零延迟测量，也不能排除分离残留造成误亮。

修复候选自相竞争：新人确认或自适应模板更新后，淘汰已不满足“远离全部已知人物”条件的旧候选，避免同一人的旧候选继续压低其正式身份的匹配置信度。原识别和学习阈值均未下调。相同真实模型输出、相同 1.5 秒窗口与 `5807094` 比较，重叠样本匹配数从 9/20 增至 12/20，加噪样本从 10/19 增至 11/19，人数均保持 2；单人、先后发言和 4 秒文件测试未退化。[候选清理证据](evidence/identity-candidate-reconciliation.json)。匹配数量不是人工标注准确率。

另比较相同录音的 1.5 秒与 3 秒独立窗口，按全局固定身份对应计算整段分离 SI-SDR，漏识别的静音也纳入评分。使用修复后的同一代码：

| 场景 | 1.5 秒窗口 SI-SDR（dB） | 3 秒窗口 SI-SDR（dB） |
| --- | --- | --- |
| 单人 | 7.40 | 9.47 |
| 两人重叠 | 0.47 / -1.15 | 13.15 / 2.01 |
| 先后发言再重叠 | 2.44 / 2.00 | 10.79 / 3.88 |
| 降低音量并加噪的重叠 | -0.20 / -1.16 | 13.11 / 2.01 |

据此把主程序默认窗口改为 3 秒，保留用户自行输入更短/更长窗口的能力；设置在主程序和文件程序各自的本机资料库 metadata 中保存。代价是额外等待采样，不能宣称低延迟。没有将“先 1.5 秒、后 3 秒”方案启用，因为本地探索中它在加噪样本退化；也没有启用简单拼接历史音频的上下文方案。以上只有两名英语说话人的合成混合样本，不代表现场中文、远场、已有错误声纹的恢复或所有串音问题都已解决。[3 秒窗口证据](evidence/identity-stable-window.json)。

69 项自动测试通过，包含静音人物的发言显示、时间轴同步、停播熄灭、窗口传递到实时与文件处理、重启设置恢复、非法输入拒绝和旧候选不干扰已确认人物。安装 diart 可选依赖后，基线真实模型再次处理公开单人 2.87 秒录音，发现 1 人并有输出，RTF 约 0.38；没有打开真实音频设备。

## 2026-10-15：diart 接入准备与限制

本机安装 diart 0.9.2 / pyannote.audio 3.3.2，保留原 torch 2.5.1 CPU、numpy 1.26.4。新 matplotlib 与 pyannote.core 5 的 `get_cmap` 接口不兼容，现锁定 matplotlib 3.8.4、pandas 2.2.3；实际导入及 `pip check` 通过。可选安装入口为 `scripts/setup.ps1 -Diart`，环境快照在 `requirements-diart-tested.txt`。

新增 `scripts/validate_diart.py` 与 `selective_hearing.diart_probe`，调用真正的 `SpeakerDiarization` / `StreamingInference`，从录音文件输出 RTTM、人物时间段和处理速度；复用上游文件 padding 并裁剪输出到录音范围。针对上游会吞掉推理异常的行为，捕获错误并拒绝导出部分结果为成功。该入口不打开麦克风、不播放声音、不修改日常声纹库。

标准分段使用 [pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0)，声纹使用官方支持的公开 SpeechBrain ECAPA。分段模型要求用户接受 Hugging Face 条件并登录，本机无登录凭据；因此真实预训练 diart 尚未运行，主程序继续使用现有后端。只验证了真实 diart 库配合合成测试模型时的流式程序连接、时间范围和错误处理，不能将其作为识别质量证据。完整 diarization 输出不等于分离波形；后续还需验证与持久身份和选择性播放的对接。[环境状态](evidence/diart-environment.json)。

## 2026-10-15：取消人物静音后恢复播放

复现了控制状态错误：初始 `all`，关闭人物再打开后残留 `TrackSelection(default_enabled=True, overrides=((speaker_1, True),))`。这会继续按身份筛选；即使原始输入 RMS 为 0.1，没有已识别音轨的块仍输出零值。直接点已开启人物的“听他”也会误进入同一状态。

`OutputControl.set_track` 现在移除与默认策略相同的冗余开关，最后一个排除被取消时恢复 `all`。若仍有人关闭则保留其排除；从全部静音逐个开启时仍保持默认静音，不把未知声音放出。切换不清空播放队列、不倒回时间轴、不改变音量。

54 项自动测试通过。新增回归覆盖有/无识别音轨、重复切换、保留其他人物静音、全部静音后单独开启、实时和文件播放回调，以及实际 Tk 按钮到实时输出回调的路径。无识别音轨时，按钮切回后下一软件回调恢复正确时间位置和音量的原声。本次没有打开真实麦克风或扬声器；这修复控制状态造成的静音，不代表筛选模式的漏识别、推理空缓冲和设备延迟已经消除。

## 2026-10-15：运行中删除资料

用户反馈点击删除没有反应、没有确认框。旧版在收音、播放或文件处理期间直接返回，只在提示栏要求先停止，与默认自动收音的流程冲突。现在删除首先显示归属当前窗口的确认框；确认后停止音频、取消自动启动，等待实时推理退出或文件任务结束通知后再删除。等待期间不允许重新开始收音或导入文件，取消确认则保留原运行状态。

删除后保持停止、刷新人物库并清除旧文件播放结果；旧代次的识别事件不能恢复已删除卡片。删除失败保留资料和卡片，提示原因并允许重试。58 项测试通过，新增覆盖运行中弹窗与取消、等待后台退出、丢弃旧事件、取消文件处理并清除旧音轨、存储错误后重试。本次只操作测试专用临时人物库，没有删除用户实际资料或开启音频设备。

## 2026-10-15：持久人物资料与学习

使用本机 SQLite 事务保存人物 ID、名字、192 维初始及学习向量、有效语音统计。目录为用户 `Documents/SelectiveHearing/profiles/`，实时和文件测试分库。新增人物在推理线程中立即提交，名字在主线程单独更新；事务避免半写入，名字不会被后台旧快照覆盖。删除编号不复用；已删除人物的旧推理线程不能将其重新写回。候选、原始录音不进入资料库。启动校验模型标识、向量维度和数值；异常资料报错保留，不默默重置。首位暂定人物也保存并保留确认状态。

持续学习采用“初始模板 + 自适应质心”，无需改动模型权重。已经成功匹配、有效语音至少 1 秒、相似度至少 0.55、领先其他人物和候选至少 0.15 的片段才有资格学习；与初始模板相似度还需至少 0.35。每次最多按 3 秒语音加权，历史有效权重上限 20 秒，更新后质心与初始模板相似度不能低于 0.65。初始模板永久保留，避免无约束地沿错误匹配漂移。以上是工程门槛，不代表标定过的概率或现场准确率。

48 项测试通过，包含：保存后新建实例恢复人物和名字、关闭窗口时未回车的改名、候选不落盘、学习结果重启保留、低置信度不学习、删除不复活、不复用 ID、损坏或不兼容资料不覆盖、模型加载期间用户的收听选择保留。新增 `scripts/validate_profile_learning.py` 使用真实 ECAPA/Silero，在两个公开英语说话人上验证：各人第 1 句前 1.5 秒登记，第 2、3 句按实时窗口学习，第 4、5、6 句仅作测试。每次测试使用独立的冻结副本，测试片段不更新之后测试用的声纹。

| 正确匹配 | 7 | 8 |
| 错配到其他人物 | 0 | 0 |

两人的学习更新分别为 4 / 2 次，重建资料库实例后名字和学习模板保持一致。[留出测试记录](evidence/profile-learning.json)。这项测试隔离声纹匹配，输入为公开单人语音，未证明混合录音、远场、中文现场或整体收听体验改善。不能承诺准确率随使用时长单调上升。

- 初始预训练输出有任意增益，直接播放会严重削波。现已通过对混合波形做双路最小二乘增益拟合修复；不把拟合残差添加到人物轨道。下表结果均来自修复后版本，两份样本所有输出的削波比例为 0。

| 场景 | 输入时长 | 计算总耗时 | 实时因子 RTF | 确认身份 | 人 1 / 人 2 的 SI-SDR 改善 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 从开头混合两人语音 | 17.06 s | 6.72 s | 0.394 | 2 | +9.01 / +16.60 dB |

**尚未稳定解决的问题：**第二份样本在人 2 单独发言时部分输出未被可靠匹配，在 8–12 秒的重叠区间人 2 整块缺失。这使该人的整段指标仅改善 0.94 dB。两份样本最后 1.06 秒也因短片段身份匹配失败而静音。保留了这些失败，没有用混合声补齐。当前版本适合验证流程，不能承诺持续稳定地只听选中人。

## 数据与评分方法

公开输入来自 [SpeechBrain 的 ASR 测试样本](https://github.com/speechbrain/speechbrain/tree/9ef9a3478a9fbc9cc31e365cc403180132fac3ac/tests/samples/ASR)，取两名说话人各六句不同语音，句间加 150 ms 静音，先按各人整段 RMS 调整后数字相加。arrival 场景移动最初各 4 秒以模拟先后出现，后面使用剩余语音，不用重复同一句凑确认次数。

模型 API 只接收生成的单声道混合文件。干净音轨只在独立评估脚本内计算 SI-SDR。整份文件只允许一次全局身份对应，不逐块交换身份“优化”分数；未识别的零值也计入评分。SI-SDR 不代表现场可懂度或识别准确率。这是两份由同一组英语样本构造的小实验，不能外推为普遍性能。

原始统计：[overlap 评分](evidence/overlap-evaluation.json)、[overlap 分块](evidence/overlap-report.json)、[arrival 评分](evidence/arrival-evaluation.json)、[arrival 分块](evidence/arrival-report.json)。包含输入文件 SHA-256；音频留在本机，不上传仓库。

复现（完成模型安装后）：

```powershell
.venv\Scripts\python.exe scripts/download_samples.py
.venv\Scripts\python.exe scripts/validate_models.py
.venv\Scripts\python.exe scripts/validate_models.py --layout arrival --output results/arrival-validation
```

下载脚本读取固定 Git commit 下的公开 WAV。已安装 GitHub CLI 时使用其正常认证，其余情况使用公开 API；不打印或保存凭据。评分脚本不访问麦克风，也不播放声音。

3. 连续分块边界的听感、交叠融合、长时间运行、按钮切换到耳内声音的真实延迟。

当前绿框和“正在说话”提示跟随已处理音频的播放时间轴，不代表无延迟的现场发言指示。模型为双人分离，单人输入也可能被拆为两路；VAD 和身份匹配只部分缓解这个问题。

## 官方实现依据

- [Torchaudio Conv-TasNet 模型与预训练 bundle](https://github.com/pytorch/audio/blob/v2.5.1/src/torchaudio/pipelines/_source_separation_pipeline.py)：8 kHz、两路分离；本项目使用同一 factory 和对应权重。
