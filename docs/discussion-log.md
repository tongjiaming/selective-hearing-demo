# 讨论与决策记录

首次整理于 2026-10-10，2026-10-13 追加实现记录。本文为讨论整理稿，不是逐字聊天导出。后续明确变更覆盖旧方案。

## 1. 项目目标

2026 Step 黑客松方向：可选择听谁说话的耳机 Demo。希望新颖、实用，结合软硬件与模型；先做最小可演示版本。

用户接受一定漏音和延迟，但很长延迟不能被描述成“轻微”。只听选中人必须覆盖两人同时讲话。

## 2. 最初四状态与设备分工

最初约定两人场景：只听 A、只听 B、都听、都不听。建议 A/B 先各单独说几秒作为登记样本，尚未验证。

曾考虑 AirPods → iPhone → 局域网 → PC 推理 → iPhone → AirPods。用户明确模型可以放 PC，不默认改为手机麦克风。

## 3. 简化为 Windows 直连

用户提出：“感觉可以不带 iphone，直接耳机和 windows PC 直连”。

当前方案据此改为 AirPods 麦克风和播放都直连 Windows，界面与推理集中在 PC。iPhone 桥接不再属于当前实现范围。

已核对普通蓝牙收音/播放能力，但未完成 AirPods 周围人声拾音或延迟实验。

## 4. 自动发现新人

用户提出：“我希望模型听到新声音之后自动识别并添加一个按钮”。

因此，自动说话人发现已从后续想法提升为当前需求。手动登记不再是期望的最终交互；可作为隔离模型问题的中间实验。

建议但尚未单独确认的交互：新人默认开启、全部静音覆盖新人、识别中状态、手动改名、正在讲话提示。

## 5. Step 模型核查

用户询问 Step 是否能完成相关任务。

核查发现 StepAudio 2.5 ASR 文件接口支持说话人标签，但为异步离线处理，身份跨任务不保证，且不输出分离波形。公开 Realtime / ASR / EditX 文档未找到完整满足此需求的能力。

没有调用模型验证，也不能排除内部未公开模型。

## 6. 非 Step 候选

用户询问非 Step 模型。候选包括：

- diart：流式分段与增量聚类，驱动按钮。
- Nemotron-3-Diarization：流式身份维护的另一候选。
- WeSep / REAL-TSE：根据参考声音提取目标波形。
- Hearpoint / Look Once to Hear：耳机实时提取研究和工程参考。

当前建议 diart + WeSep 作为实验起点，尚未确定最终技术栈。

## 7. diart 是否认人、选中后怎样控制

用户继续确认 diart 能否区分说话人，以及如何只听选中的人。

当前连接思路：

1. diart 区分本次会话中的人，维护标签。
2. 自动截取该人单独讲话的可靠片段。
3. 按钮绑定标签与参考声音。
4. 选中按钮后，将参考声音和当前混合收音交给提取模型。
5. 播放提取结果；都听走原始混合音频，都不听停止软件输出但保留收音。

核心待验证点是自动参考样本质量、连续推理速度、身份稳定性和切换时序。

## 8. 本次授权与产物

用户同意创建 GitHub 私有仓库，并上传当前讨论。

2026-10-10 当次仅建立文档仓库；当时没有进行开发、训练、收音或部署。之后的开发授权见下方第 10 节。

## 10. 2026-10-13：开始实现

用户要求「在这个仓库里，基于我们的方案先做起来吧，能做到什么程度算什么程度」，并答复「稍后连接，先做程序」。本次据此实现 Windows 本地原型并使用公开样本验证，不启动麦克风。

首版采用 Conv-TasNet 双人分离权重、ECAPA 声纹特征和 Silero VAD。diart 的模型许可门槛及 WeSep 约 1 GB 的预训练包使它们没有成为本次首版后端；这不是对其质量的结论。现有结构先验证波形分离、自动人物按钮、按人切换与原声/静音链路。

实现为 4 秒非因果分块处理，明确存在较大缓冲延迟。身份只在当前会话内有效，至少两块确认，暂限两人。未匹配目标静音，全部静音优先于新人物发现。

实际完成范围和测量结果统一维护在 [实现与实测](implementation.md)，不把代码实现等同于 AirPods 实机验收。

## 11. 2026-10-15：简化启动与说话人控制

用户明确要求每人独立「听他 / 不听他」、不限于两个会话身份，并询问独立背景音。现已实现独立开关和多人会话登记；当前模型仍只能同时分离两路人声，背景轨尚不支持。

用户进一步要求「启动了自动加载模型并收音」「导入音频测试的放另一个独立的文件/程序里」「每个说话人可以自定义名字」。主程序据此改为自动加载后开始收音，加载期间点停止可以取消；文件导入、试听和导出迁移到独立文件测试程序。人物卡片可直接改名，当前会话内保留，文件导出的报告也保留名字。

本次按新的自动收音要求，实际打开当前默认音频设备短时验证；播放增益为零，未保存录音。设备运行结果与公开样本测试详见 [实现与实测](implementation.md)。

## 12. 2026-10-15：两人被登记成多人

用户反馈现场实际只有两人，却生成很多人物。使用实时 1.5 秒窗口在公开双人混合样本上复现；旧规则将一次低相似度片段直接永久登记，短窗声纹不稳定时会重复建人。

改为区分匹配、待确认和新增身份：首位人物保持首次发现即可操作，后续新人需跨块重复证据，疑似重复与歧义片段不建人，候选限时清理。短片段匹配使用单独阈值；正式人物仍无两人上限，不强行把未知声归到已有两人。验证和尚存的短窗匹配、音质问题见 [实现与实测](implementation.md)。

## 13. 2026-10-15：重启保留人物，并持续学习

用户要求每个人的声音特征持久化，并明确要求软件能够在使用过程中改善人声分类。现在本机保存已登记人物的名字、初始声纹和学习声纹，重启恢复；未确认候选不保存。正常使用时，从高可信匹配中更新受约束的自适应质心，同时保留初始模板，避免误匹配不断污染身份。实时和文件测试使用独立人物库，可在停止音频后删除资料。

公开留出样本上，正确匹配由 7/8 提高到 8/8，重启后学习结果保留。现场效果以及此前的实时播放断续尚未解决，不把这次学习机制和持久化验证写成完整听感验收。详细数据见 [实现与实测](implementation.md)。

## 14. 2026-10-15：点回“听他”仍然无声

用户再次反馈关闭人物再开启后完全无声。复现发现：从原声切到人物排除后，取消排除仍残留人物筛选状态，无身份音轨的块因此继续静音。现在取消最后一个排除会恢复原声；还有其他人物关闭或默认全部静音时，继续保留筛选。54 项测试通过，包含界面按钮到音频回调的恢复验证；设备实听及筛选模式中的漏识别、缓冲断续仍未验收。

## 15. 2026-10-15：删除按钮没有反应

用户反馈删除删不掉，并确认没有弹出确认框。代码在音频运行时提前拒绝删除，默认自动收音导致用户通常会触发该路径。改为先弹确认框，确认后自动停止并等待后台处理退出，再删除资料；取消确认不影响收音，删除后保持停止，避免立刻重新登记。增加相关回归，58 项测试通过。

## 16. 2026-10-15：发言绿框、识别改善、diart 与窗口设置

用户要求已保存人物在说话时亮起类似会议软件的绿框，并反馈重复建人、认错人、漏识别和重叠串音都有。增加与处理后音频时间轴同步的发言边框，静音不影响显示；清理已经归入正式身份的旧候选，避免互相竞争。公开双人重叠样本在相同 1.5 秒窗下，匹配数量从 9/20 增至 12/20；仍不能承诺现场问题已解决。

用户建议接入 diart。已安装兼容依赖并准备完整 diart 独立验证入口；真实分段权重因本机未完成 Hugging Face 授权/登录而尚未运行，不把安装和合成模型的程序测试说成识别效果验证，也未切换主程序。

用户要求窗口在软件内配置。实时与文件程序均可输入 1–10 秒，并分别保存设置。相同公开样本上 3 秒窗口的整段分离评分优于 1.5 秒，因此主程序默认 3 秒，用户仍可自行缩短。窗口加长会增加采样等待；当前每块音频独立分离，但共享持久人物库和学习结果，尚无跨块交叠融合。69 项自动测试通过，详细边界见 [实现与实测](implementation.md)。


## 17. 新设备不显示、学习 0 段与远声收音

用户报告新接设备未出现在列表。检查确认旧 UI 缺少自动枚举、收音中刷新直接返回；改为每 4 秒独立进程检查，新增设备只更新列表，用户选择后安全切换，拔出使用中的设备则停止。实际系统枚举已看到新耳机的输入与输出端点。

用户询问已识别人物为何学习 0 段：原计数仅包含初始建档后的可靠追加学习。文案改为“初始声纹已保存 · 追加学习 N 段”，不把初始声纹或每次匹配虚算为学习。

用户询问远距离声音听不到是否硬件问题：尚无原声对照结果，不能确定。建议停止、取消自动识别后重新开始做原声测试，先区分采集/系统处理与算法门槛；用户随后反馈原声似乎也听不到，排查重点转到输入设备/输入增益/驱动处理；系统默认输入为 Realtek 麦克风，但用户纠正后确认软件实际选择新耳机麦克风。只读查询该耳机捕获端点的 Windows 输入音量约 53.3%，未静音；尚未做提高输入音量或同距离换电脑阵列的对照。未宣称硬件故障，未擅自改系统输入音量或降噪设置。


## 2026-10-15：修复人物数量失控并验证分类

用户反馈即时建档后说话人数量爆炸，要求把分类工作做好。本机仅检查聚合统计，旧资料已有 82 人、117 段特征，其中 64 人只有一次观测，没有发生合并。没有保存或上传用户麦克风录音或声纹。

本次保留首人快速控制，取消每次匹配失败就直接新增人物；允许同一人的两路分离输出共用人物身份，明确不同的两路才建立不可合并关系。短窗用过去最多 3 秒声音补充上下文，只播放当前片段。增加独立参考标志，重叠上下文不重复参与可靠近邻投票和模板学习。所有更新按用户约定清空旧学习数据，保留窗口设置。公开样本、反例和限制详见实现文档及分类回归 JSON。
